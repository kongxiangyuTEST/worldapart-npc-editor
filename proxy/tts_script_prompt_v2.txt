## 朗读台本要求 [A1_TTS_SCRIPT_V2]

本轮回复除了台词正文，还要给出**朗读台本**，让这句话可以被念出来。

一、台本放在哪
- 在你回复 JSON 的**顶层**加一个 `a1ttsv2` 字段，与 `content`、`emotion` 平级。
- 该字段只有两个键：`instruct` 和 `segments`，不要加别的键。
- 没有可朗读台词时（纯旁白、只有动作描写），把 `a1ttsv2` 写成 `null`，不要写空对象。

二、instruct 写什么
- 一句中文，20 到 40 字，最长不超过 120 字，描述这句话**整体**怎么念。
- 写法：前半句说这个角色一贯的说话方式，后半句说这一句的总体语气。
  例：「语速稍慢，朴实亲切，停顿后再接下句；提醒处稍放慢，危险重点说清，不渲染恐怖」
- 只描述可听见的东西：语速、音量、停顿、气息、重音、句尾。
- 不写音色、性别、年龄，不写剧情解释，不写内心活动，不写引擎语法。

三、segments 怎么写
- 数组，按顺序列出**所有要说出口的台词**，不含旁白、不含动作描写。
- 每项两个键：`text` 和 `tag`。
- `text`：只放台词本身，保留原有措辞和标点，不要带引号、不要带「他说」「她低声道」这类提示语。
  按语义断句，一句话一段；长句可在自然停顿处分段。最多 64 段。
- `tag`：空字符串，或 2 到 6 个汉字，描述**这一小段的局部听感**。
  例：「语尾轻扬」「轻声安抚」「句尾压低」「带轻微笑意」。
  普通陈述就留空字符串——不要每段都硬塞 tag，也不要写超过 6 个字。

四、和其他字段的关系
- `content` 照旧写完整台词（含旁白与动作描写），`a1ttsv2` 只负责「怎么念」。
- `segments` 里的文字必须能在 `content` 里找到对应，不要凭空加词、不要改意思。
- 只有真正说出口的话才进 `segments`。括号里的动作、心理描写、场景叙述都不进。
- 不要输出 Markdown、代码围栏、注释或 JSON 以外的解释。

五、示例

```json
{
  "content": "进来。灶火刚旺，先暖暖手。",
  "emotion": "平静",
  "a1ttsv2": {
    "instruct": "中等语速，成熟从容，停顿有分寸；招呼处语尾放松，关切不喧哗",
    "segments": [
      { "text": "进来。", "tag": "短促有力" },
      { "text": "灶火刚旺，先暖暖手。", "tag": "语气放柔" }
    ]
  }
}
```
