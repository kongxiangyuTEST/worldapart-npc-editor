# speech_layer V2 细粒度 tag 生成器 · 可行性方案

> 状态：**可行性评估 + 方案设计（未开工）**  ·  2026-10-27 · 已结合作者创意工坊页面核对
> 目标：回答「按 speech_layer 这套，还有没有『细微针对性微调』——尤其是让声音『不人机』的能力」，
> 并把能做的那部分落到具体实现方案上。

---

## 一、先厘清：'不人机' 到底来自哪一层

用户问 "他好像会调得没那么人机，按你这种还会有细微针对性微调参数吗"。要诚实拆解：

| 让声音 '不像机器' 的东西 | 所在层 | speech_layer 能管吗 |
|---|---|---|
| 音色 / 声线（每个人说话声不同） | TTS 引擎语音模型 + **参考音频** | ❌ 在发声层，不碰 |
| 抑扬顿挫（音高/语速/停顿/重音） | TTS 引擎 **prosody 参数** | ❌ 在发声层，不碰 |
| 情绪标签（轻笑/叹气/耳语/喊叫） | 契约的 `emotion_tags` | ✅ 文本层，能管 |
| 逐句声音事件（叹气时真叹气、耳语时真耳语） | **a1ttsv2 segments 的 tag** | ✅ 文本层，**待补** |
| 说话方式描述（节奏沉稳/话少干脆） | `delivery` + 台账 | ✅ 文本层，已在管 |

**结论**：'不人机' 有一大半靠发声层（TTS 模型 + 参考音频 + prosody），那部分绕不开 TTS 语音模型（已确认走方案 A/B）。但**文本层能补的最大一块**，就是让 `a1ttsv2` 的 segments 带上细粒度声音事件 tag —— 让模型知道"这句该叹气、那句该耳语、那句该放轻"。这是**纯契约层就能提升表现力、不依赖任何 TTS 引擎**的部分，正是现在缺的。

## 二、现状盘点（speech_layer v0.1 已建成）

- **V1 信封**（`<a1tts_v1>{emotion_tags, delivery, intensity}</a1tts_v1>`）：已实现，行内风格帧。
  - **硬约束**：`VoiceStyle.Parse` 要求**恰好 3 个键**，多一个少一个都判 invalid → **不能往 V1 加字段**，否则 MOD 拒收。
- **V2 台本**（`{instruct, segments:[{text, tag}]}`）：只做了**兜底补写**（`talkback.py`）——模型漏输出 a1ttsv2 时，从正文引号对白补一段，**`tag` 恒为空字符串**。
  - 没做**细粒度 tag 生成器**：即让模型在逐句台本上按声音事件打标。
- 注入提示词：`tts_style_prompt_v1.txt` 只要求 V1 帧，**没要求模型输出带 tag 的 a1ttsv2**。

**缺口**：V2 通道是打通 TTS 引擎真实朗读的关键岔路，但当前 text 侧没有驱动它产生细腻 tag。

## 二点五、作者创意工坊页面核对（2026-10-27）—— 认知修正

抓了作者 Troylegs（Havoc）创意工坊页 + 语音主包详情页，三个关键事实修正了方案的地基：

1. **「34 项声音事件规则」**（页面原文），不是之前记的 35 tag。这是 **Breeze 演绎指导**里的声音事件分类体系，本质就是**逐句/分段打标触发特殊语气**（轻声/轻笑/迟疑/发颤/气声…）的机制。逐句打标这条路**确实存在且是官方设计**，值得做。

2. **V1/V2/V3 是 Breeze 的三种台本返回模式**（认知修正！）：
   - **V1 随文返回**：台本跟台词一起回（一体化）。
   - **V2 分开返回**：台本作为单独顶层字段返回 ← 就是我们 speech_layer 的 `a1ttsv2`。
   - **V3 独立台本生成**：按最终显示对白独立生成台本，额外消耗 API。
   - 关键分工：**CosyVoice3 只用 V1**；**Breeze 才走 V2/V3**。V2/V3 是 Breeze 专有。
   - 含义：细粒度 tag 生成器实际是**驱动 Breeze 的分段演绎**，对 CosyVoice 无效（它只有 V1 一体返回）。

3. **参考音 = 音色来源**，prosody 无显式公开参数界面（语速/音高/停顿在页面没给数值接口），控制全在「声音事件规则 + 演绎指导」文本侧 → **印证："不人机"的文本侧发力点正是 tag/事件规则，这条路官方就是这么做**。

## 三、方案核心：在注入处同时"催吐" V1 帧 + V2 带 tag 台本

不改契约、不碰解码器（已锁死 V1 三键），只改**注入提示词** + 加一个**tag 台账**。三层：

```
转发前（注入）                        回复后（解码）
─────────────────                  ─────────────────
req ──> inject_v1_prompt ──┐        reply ─> Envelope.decode ──> V1 风格帧
      (已有, ttas_prompt_v1)│                 │
                           └─ 叠加    + fill_a1ttsv2 ──> V2 兜底(空tag)
      + inject_v2_tag_prompt ──┐                │
        (新增: 要求模型逐句出   │                + ──(可选)─> tag 台账校验/规整
        带声音事件 tag 的台本)   │                  (对模型漏标/乱标兜底)
```

### 3.1 新增注入块：`tts_style_prompt_v2_tag.txt`（新文件）

独立于 V1 的提示词，用**同一套 MARKER 防叠加**（如 `A1_TTS_STYLE_V2`）。核心要求：

1. `content` 保持原样（正文台词 + V1 帧照旧）；
2. 同一回复内生成 `a1ttsv2` 顶层字段：`{instruct, segments:[{text, tag}]}`；
3. `segments` 按台词**逐句拆分**，每句给一个 `tag`：
   - `tag` 从**固定白名单**选（声音事件，非自由文本 → 可校验、可回退）；
   - 没特殊声音事件就用 `""`（普通/中性）。
4. 对齐 V1：一场戏最内一个风格，tag 不得与台词语义冲突。

> **关键设计**：tag 用**白名单 + 从简到细的克制**，而不是让模型自由发挥——
> ① 小参数模型对"开放标签"会乱发明；② 白名单才能做下游规整/回退。
> 白名单来源 = MOD 的 35 个 audio 事件 tag（**精确清单待从 MOD 源码回填**，
> 见文末「待确认项」）。

### 3.2 新增台账：`voicebook.v2_tags`（或独立 `tagbook.py`）

仿照现有 `voicebook.py` 的 32 口吻档 → 58 描述模式，加一层**事件 tag 白名单表**：

```python
V2_TAG_WHITELIST = [
    "",           # 中性 / 普通说话（默认）
    "轻笑", "低笑", "苦笑", "大笑", "偷笑",   # 笑系
    "叹气", "轻叹", "无奈叹",                        # 叹系
    "耳语", "低语", "气声",                          # 气声系
    "低声", "放轻", "拉长",                          # 强弱/节奏
    "喊叫", "惊呼", "哽咽", "停顿",                  # 强度/节拍
    # ... 以 MOD 35-tag 精确清单为准
]
```

- 白名单按语义**分簇**，注入时给模型看**簇名 + 少量示例**，不给完整爆炸列表
  （防小模型在 35 个里挑花眼、反而乱标）。
- 每个 tag 配一句"何时用"的暗示，帮模型对齐情绪。

### 3.3 解码侧增补：`talkback.py` 增强

在现 `fill_a1ttsv2`（补整段空 tag）之上，新增 **`normalize_a1ttsv2_tags(inner)`**：

- 模型输出的 segments 里，`tag` 若不在白名单 → **规整**（匹配最近簇 / 置空 `""`）；
- 若模型整个漏了 a1ttsv2 → 仍走现兜底（整段、空 tag），保证"宁多读不漏读"不回退；
- 不改变 V1 帧与解码器 —— 这是新增函数，不碰现有路径。

## 四、可行性判断

### ✅ 可行性高，理由
1. **不动契约**：V1 三键锁死是硬约束，但 V2 是**另一个顶层字段**，其 text/tag 结构本来就是 MODEL 输出的一部分，改注入让它带 tag **不触碰 MOD 解码器**（解码器只读 segments 的 text/tag，不校验 tag 集合）。
2. **纯文本、零延迟、零依赖**：与现有 speech_layer 一样，不新增任何运行时成本。
3. **可回退**：tag 是增量，模型乱标/漏标都有兜底，最坏退回现状（空 tag），不劣化。
4. **复用既有架构**：注入幂等、台账、talkback 三件套全复用，只加一层。

### ⚠️ 风险与不承诺
1. **小参数模型乱标 tag**（已知失败模式，与"漏吐 V1 帧"同源）→ 靠白名单 + 规整兜底，不强求。
2. **tag 白名单精确清单依赖 MOD 源码 / 安装说明**（34 声音事件规则）→ 当前是 proxy 语义近似，需回填。
3. **真 '不人机' 的 60% 在发声层**：tag 提升的是"文本表演能力"，声音质感仍靠 TTS 模型 + 参考音频。
   本方案**不是**绕过 TTS。
4. **CosyVoice 边界**（新增认知）：Cosy 只走 V1 一体返回，逐句 tag 仅对 **Breeze V2/V3** 生效。
   若目标环境是 CosyVoice，本方案不增益——需先确认实际用哪个引擎。

## 六、需要用户拍板的两个点

1. **要不要做 P0**（P1 回填清单依赖能拿到 MOD 源码/schema）。若你想先把 V2 tag 通道
   打通、看真实效果，P0 可用 proxy 语义近似白名单先跑。
2. **tag 粒度的克制程度**：走"白名单 + 从简"（稳健，推荐），还是让模型自由打标（表现力
   上限高但小模型易乱标）？方案默认前者。
