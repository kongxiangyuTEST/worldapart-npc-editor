# 音色控制：所有试过的通道与结论汇总

> 2026-10-28 深夜 · 这是个**负面结论汇总**，目的是一次性堵死所有"再试试别的"的念头，
> 免得以后重复踩。每一条都有实测数据，不是推测。

---

## 一、根本矛盾

Breeze 是「参考音色 + 自然语言指令」的模型。**指令是生成条件，不是风格开关。**
指令一变，整段声学统计跟着变 —— 包括音高。

实测（同一句话、同一 NPC、同一参考音，只改 instruct）：

| instruct | 基频 | 相对纯基线 |
|---|---|---|
| 纯基线 subtle | 222.2 Hz | — |
| +句间留半拍 | 217.2 Hz | -2.27% |
| +重音压实 | 213.1 Hz | -4.09% |
| +重点处放慢 | 209.3 Hz | -5.80% |
| +闲聊（无音色词） | 227.4 Hz | +2.33% |
| +威胁 | 238.0 Hz | **+7.11%** |

对照幅度：

| 变量 | 音高极差 |
|---|---|
| 文本内容自然起伏 | 5.53% |
| 角色基线差异 | 5.57% |
| **我们自己加的表演层** | **8.29%** |

人耳分辨"换人"的阈值大约在 5–7%，所以表演层的偏移正好落在"听得出变了"的区间。

**官方数据佐证**：BreezeBlue 自己的 Voice Direction Benchmark 报告
「Speaker similarity 0.67 while directed」——官方也承认带指令时音色只保持 0.67 相似度。
这不是我们的用法问题，是模型特性。

## 二、试过的旁路，全部无效

### ① `segments[].tag` 内嵌进 input（期望：不打标只发音）

Breeze 官方文档说支持 Inline Vocal Events：英文 `(laugh)` `(cough)` `(sigh)`，
**中文用方括号** `[笑]` `[咳嗽]` `[清嗓子]` `[叹气]`。

但 MOD 用的不是官方 Python 推理，而是 `audiocpp_server.exe`（独立实现）。实测：

| 写法 | 时长 | 结论 |
|---|---|---|
| 无事件 | 4.48s | 基准 |
| `[笑]语法` | 5.52s | **被念出来 +23.2%** |
| `[叹气]` | 6.80s | 被念出来 +51.8% |
| `[清嗓子]` | 6.08s | 被念出来 +35.7% |
| `(sigh)` | 6.32s | 被念出来 +41.1% |
| `[轻笑]`（非官方词） | 6.80s | 被念出来 +51.8% |

另外还试过 `<|轻笑|>` / `<轻笑>` / `【轻笑】` / `{轻笑}`，同样全部被念出来（+16~52%）。

**结论：这个 audiocpp 实现没有内联事件能力，任何标记都被当台词念。**
（换官方 Python 推理也许可用，但 MOD 不支持。）

### ② `guidance_scale`（cfg）提高指令遵循

官方建议 Direction 模式用 `cfg_scale=4`。实测：

| cfg | 时长 | subtle 基频 | hard−subtle 差 |
|---|---|---|---|
| 1.0 | 5.20s | 223.9 Hz | +2.39% |
| 2.0 | 5.52s | 210.4 Hz | — |
| 4.0 | 4.96s | 235.0 Hz | **+1.70%** |

**cfg 提高后音色反而更漂（+5%），角色区分度还变小了。** 保持默认 1.0。

### ③ 只改措辞，把"音色词"从表演层去掉

把 12 条含音色词的表演描述（轻声/音量/冷硬/明亮/气息）改写成只谈语速停顿。
偏移从 +8.3% 降到 ±2–6%，**没消除**。因为「闲聊」这种完全无音色词的描述也能 +2.33%。

### ④ 合并成单段（减少请求次数）

先验证了链路确定性：同一句话连跑 3 次，md5 完全一致（`4e3eba1486d2`）。
**跨请求不会引入任何差异。** 所以合并对音色零收益（但减少了请求数和拼接点，保留）。

## 三、结论

**在这个引擎上，「音色绝对统一」和「每句表演不同」不可兼得。**

| 想要的 | instruct | 代价 |
|---|---|---|
| 音色绝对稳 | 恒等于角色基线 | 只有语速/停顿/句尾，没有"轻笑""气声" |
| 有表演细节 | 每轮追加描述 | 音色漂 2–7%，听感像换人 |

当前选择：**`tts_instruct_mode = profile`（音色优先）**。

三档可切换（`ai_config.json`）：

| 档位 | instruct 内容 | 适用 |
|---|---|---|
| `profile`（默认） | 只用角色基线，同 NPC 每轮一致 | 音色优先 |
| `profile_model` | 基线 + 模型自写的场景描述 | 折中，漂 3–7% |
| `full` | 基线 + 我们的表演层 | 情绪最强，漂最多 |

## 四、还能走的路（未验证，成本较高）

1. **换 TTS 引擎**：IndexTTS2 有「音色-情感解耦」（GRL 对抗训练），声称"换情绪不换人"。
   但 MOD 只接 Breeze/CosyVoice，换引擎等于换 MOD。
2. **CosyVoice3**：MOD 支持，但它只有 V1 一体返回，且我们没测过它的情感控制能力。
   如果 Cosy 的情感控制更好，可以考虑。**这是唯一还没试过的引擎侧选项。**
3. **多个参考音**：给同一 NPC 准备几个不同情绪的参考音（比如平静版/激动版），按情绪切换。
   代价是音色也会跟着换（因为参考音就是音色来源），本质上还是同一个取舍。

前两条都需要换模型或换引擎，第三条等于换音色。**没有便宜的路了。**
