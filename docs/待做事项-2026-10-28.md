# 10-28 晚上：三处问题的修复记录

用户实测三个角色（苏倾盏/纪小蝶/柳秀娘）后报了三个问题，都已定位并修好。

## 问题一 & 二：同一根因 —— 结尾引号没闭合

**症状**

| 现象 | 角色 |
|---|---|
| 第三段台词没念 | 纪小蝶 |
| 第一段旁白被念出来 | 苏倾盏 |
| 第二、三段没念 | 苏倾盏 |

**根因**：游戏回复经常这样收尾（开引号比闭引号多一个）：

```
才正经道：“那便请说吧。是嫌我这阵子熬得晚…我好了个准备。
                    ↑ 开 3 个，闭 2 个，最后这段没闭合
```

旧实现用「必须成对」的正则 `[“「『]([^”」』]*)[”」』]`，
最后那段最长最关键的台词匹配不上，于是：

- 若有 ≥2 段已配对 → 判为「分隔式」，**只取已配对的** → 最后那段被丢掉（没声）
- 若只有 1 段已配对 → 判为「强调式」，**整段都念** → 旁白被念出来

**修法**：新增 `_extract_spans()`，逐字符扫描，**字符串结束时还没闭合的引号也算一段**。

实测 7 条真实回复，修复前后：

| 角色 | 原文 | 修复前朗读 | 修复后朗读 |
|---|---|---|---|
| 纪小蝶#3 | 161 字 | **18 字**（只念开头） | 61 字（5 段，含缺失的那段） |
| 苏倾盏#1 | 141 字 | 整段含旁白 | 47 字（3 段纯台词） |
| 苏倾盏#2 | 216 字 | 部分丢失 | 133 字（5 段） |
| 苏倾盏#3 | 265 字 | 部分丢失 | 161 字（7 段） |

## 问题三：hard 和 subtle 听不出区别

**根因不在代码，在词表。** 原来写的是：

```
hard    话少干脆，落字有力，语气不绕弯      ← 态度词
subtle  语气温和克制，重点轻落，留有余地    ← 态度词
```

两条都是「沉稳克制」的描述，声学上是同一类。
而 `free`（柳秀娘）有「轻快」这个明确速度信号，所以一听就不同。

**Breeze 只认可听量级（语速/音量/音色/停顿/句尾），不认性格词。**

**修法**：重写原型用到的 13 条基线，每条落到 ≥2 个可听维度上：

| profile | 新基线 |
|---|---|
| hard | 语速偏快，句子短，句尾干脆收住，几乎不停顿，不拖泥带水 |
| subtle | 语速偏慢，音量偏轻，停顿明显，句尾平放略收，不抬高声音 |
| free | 语速轻快，音量适中，句尾自然散开，语气松，不刻意笑 |
| cold | 语速偏慢，音量轻，音色偏低，停顿长，句尾平直不升温 |
| solemn | 语速很慢，音量沉，长停顿多，句尾沉重落下，不轻飘 |
| bright | 语速快，音色明亮，音量稍大，句尾利落收，不拖尾音 |
| bold | 语速快，音量大，重音砸得实，句尾短促收，不含糊 |
| kind | 语速慢，音量正常，句尾柔软上托，气息温和，不喊不劝 |
| leader | 语速稍慢，音量稍大，句尾下压笃定，不乱加语气 |
| diplomat | 语速适中，音量正常，停顿匀称，句尾平收，不抢话头 |
| clever | 语速中等偏快，句中常短停，句尾轻轻上扬，不一口气说完 |
| qianer | 语速快，音高偏亮，音量正常，句尾轻快跳起，不拖长音 |
| sun | 语速稍快，音量稍大，音色开阔，句尾舒展上扬，不尖不吵 |

**注意**：`hostess` / `pet` / `natural` 没动（有硬断言），其余 45 条也没动 —— 只改卡片实际会用到的 13 条。

# 10-28 深夜续：半角引号 + 音色漂移

## 问题一：半角直引号 `"` 没被识别

游戏回复里**三种引号混用**，最坑的是半角直引号：

```
"推荐我？"她轻轻重复了一遍，"客官这话说得巧。…"
```

计数下来 `“”「」` 全是 0 —— 我们完全没认出这是引号，退化成「整段全念」，
于是旁白被念出来、台词结构全乱。

现在 `_OPENERS` / `_CLOSERS` 已包含 `"`（开闭同形，按在块内/块外切换语义）。

## 问题二：片段过碎 → 音色漂移

每切一段就是一次独立的 Breeze 调用，切得越碎，片段之间音色差异越明显。

**改法**

| 情况 | 以前 | 现在 |
|---|---|---|
| 引号分隔式 | 按句号切，277 字 → 7 段 | **一个引号块 = 一段**，<8 字的块并入下一块 |
| 引号强调式 | 按句号切，常见 5–9 段 | 整段 1 段（≤200 字），超长才按句拼成 ~180 字大块 |

回放 99 条历史回复：

| 指标 | 改前 | 改后 |
|---|---|---|
| 平均片段数 | 3.6 | **1.9** |
| 最多片段 | 9 | **5** |
| >4 段的回复 | 17 条 | **1 条** |

## 测试

204 全过。新增 `AsciiQuoteCase`(3) + `SegmentCountCase`(2) + `test_long_text_still_split`。

## 仍需注意

音色漂移只能"减轻"，不能"消除"——只要 MOD 是逐段调用 Breeze，段与段之间就可能有细微差异。
如果这次听完还是觉得明显，下一步可以考虑让整个回复只出 **1 个片段**（长文本交给 Breeze 服务端
自带的 `text_chunk_size=600` 去切），那是我们能控制的最小调用次数。

# 10-28 晚（第二次）：音色不统一的根因与方案

## 一句话结论

**不是分段的问题，是 `instruct` 的问题。** Breeze 的 instruct 是生成条件，
不是风格开关——只要它变一个字，音高就动 2–7%（「威胁」+7.1%），
听感就是「换了个人」。而文本本身的自然起伏只有 5.5%。

所以「每句音色统一」和「每句语气不同」在这个引擎上不可兼得，必须选一头。

## 已改

| 改动 | 说明 |
|---|---|
| 新增 `tts_instruct_mode` | 三档，默认 `profile`（只用角色基线 → 音色锁死） |
| `fill_a1ttsv2` | 默认 `with_performance=False`，instruct 只放基线 |
| `_sl_apply_style_v2` | `profile` 档下把模型自写的 instruct **直接覆盖**为基线 |
| `PERFORMANCE_DELIVERY` | 12 条含音色词（轻声/音量/冷硬/明亮/气息）改写成只谈语速/停顿/重音 |
| `tts_single_segment` | 默认 true，一轮合并成 1 段（**对音色无收益**，只为少请求） |

`ai_config.json` 当前：

```

tts_script_v2         False
tts_style_inject      False
tts_instruct_mode     profile      ← 新增，音色优先
tts_single_segment    True         ← 新增
```

# 10-28 深夜补：音色控制所有通道已试完（负面结论）

完整数据见 `docs/reverse/音色控制-实验结论汇总.md`。这里只留结论。

## 已确认无效的四条路

| 通道 | 结果 |
|---|---|
| `segments[].tag` 内嵌 input | 全部被念出来（官方词 `[笑]` `[叹气]` 也一样）—— audiocpp 不支持内联事件 |
| `guidance_scale`=4（官方建议） | 音色更漂 +5%，角色区分度反而变小 |
| 只改措辞去掉音色词 | 偏移从 8.3% 降到 2–6%，没消除 |
| 合并单段 | 链路确定性（md5 三次一致），对音色零收益 |

## 根本原因

**instruct 是生成条件，不是风格开关。** 一变就动音高 2–7%，而文本自然起伏只有 5.5%。
官方自己的 Voice Direction Benchmark 也写着「Speaker similarity 0.67 while directed」——
带指令时音色只保持 0.67 相似度，这是模型特性。

## 唯一还没试的引擎侧选项

**CosyVoice3**（MOD 支持）：它有 V1 一体返回模式，我们没测过它的情感控制能力。
如果 Cosy 在「换情绪不换人」上比 Breeze 好，那值得切。但它是另一套模型，要重新验证契约、
