# WorldApart 人物卡编辑器

一款给游戏《不问凡尘》（WorldApart）用的 AI 对话辅助编辑器。

它让你在游戏外编辑 NPC 的「用户名片」，并通过本地中转层把内容注入到游戏发给 AI 的提示词里，
让游戏里 NPC 的对话体现出你写的设定。

**本工具不修改游戏本体**，只在请求转发的过程中改写提示词，所有改动都是本地行为。

---

## 它能做什么

- **编辑 NPC 人物卡**：用户名片、预设资料、原游戏背景三段分离，改完实时写回 `.md`
- **用户名片注入**：以「角色演绎要求」的形式追加在 system 末尾，离生成位置最近、权重最高
- **AI 补全名片**：读卡片背景 + 游戏 prompt + 长期记忆，自动生成结构化设定；
  模型可选本地大模型或第三方 API，以游戏原始资料为准（玩家发言不会被当成设定依据）
- **长期记忆**：自动总结剧情、重要度分级、按轮次老化遗忘；关系里程碑受保护
- **换存档保护**：游戏记录对不上时自动暂停注入，等你确认是「同一档」还是「新档」
- **提示词管理**：INJECT 注入 + REPLACE 替换规则，存盘即生效、不用重启
- **提示词预览**：改完立刻看到命中几条、注入多少字、最终 system 长什么样
- **固定段落 AI 精简**：把每轮重复发送的长段落压缩，省 token；可一键变成替换规则、随时恢复
- **从游戏导出角色卡**（不依赖 Mod）、**提取 NPC 头像**
- **卡片对比与合并**：游戏更新后看新增 / 改动 / 删除，合并时游戏字段用新版、用户名片保留
- **上游地址切换**：本地大模型 / 第三方 API 随时切
- **服务与日志**：内置 Caddy + core_proxy 启停与实时日志

## 工作原理

```
游戏 ──HTTP──▶ Caddy 8788（转发）
             └▶ core_proxy 8789（改写 + 注入）
                   ├ 从 system 的「## 角色设定」解析 NPC 名字
                   ├ 应用替换规则（只作用于 system）
                   ├ 注入长期记忆
                   ├ 注入用户名片（追加在 system 末尾）
                   └▶ 转发给上游（本地 8080 或第三方 API）
AI 回复 ◀── 原路返回 ── 游戏显示
```

回复到达后，本轮对话会写进该角色的记忆队列，积累到一定轮数由 AI 自动总结成剧情摘要，
过时的事实按重要度逐级降级、最终遗忘。

**关键点**：游戏自带的「记忆压缩」类请求（system 里没有角色设定）会被原样放行，不做任何改写。

## 快速开始

### 直接用（打包版）

1. 从 Releases 下载压缩包，解压到任意位置
2. 双击 `WorldApartEditor.exe`
3. 第一次启动会自动生成 `ai_config.json`
4. 到「工具」页填游戏目录，点「导出角色卡」，NPC 卡片就会出现在「人物卡」页
5. 到「服务管理」填上游地址（本地 8080 或第三方 API），点「保存并重启」
6. 游戏里的「自定义 AI 模型」地址填 `http://127.0.0.1:8788/v1/chat/completions`

### 从源码跑

```bash
setup.bat          # 建虚拟环境 + 装依赖
启动编辑器.bat      # 启动
```

## 配置说明

| 文件 | 作用 | 改动后 |
| --- | --- | --- |
| `ai_config.json` | 注入语、替换规则、记忆参数、名片开关 | 存盘即生效（热加载） |
| `proxy/core_proxy_config.json` | 上游地址、监听端口、兜底密钥 | **必须重启 core_proxy** |
| `user_config.json` | 游戏目录 | 自动重启 |

**API Key 不在编辑器里填。** 对话用的密钥来自游戏设置里的「自定义 AI 模型」，
编辑器只负责转发请求头；`core_proxy_config.json` 的 `api_key` 只是游戏没带密钥时的兜底。

各配置项的含义与默认值见 `ai_config.example.json` 里的注释。

## 目录结构

```
editor_cards/        NPC 卡片（.md）
memory/              长期记忆（JSON）
prompt_samples/      游戏真实对话样本
originals/           首次保存时的原版（「恢复原版」用）
last_saved/          每次保存前的上一版（「撤销修改」用）
editor_cards_backup/ 导出/批量写入前的全量快照
portraits/           头像
diff_reports/        卡片对比报告
web/                 前端（纯 HTML/CSS/JS）
proxy/               core_proxy
tools/               辅助脚本
```

数据全部放在程序同级目录，换电脑或分享给别人时各存各的，不会互相串。

## 打包

两种包，用途不同：

```bash
build_all.bat        # 干净包 → dist/WorldApartEditor/        分享用，约 3 分钟
build_test.bat       # 测试包 → dist/WorldApartEditor_测试版/   自己用，含游玩数据
```

| | 干净包 | 测试包 |
|---|---|---|
| 用途 | 分享、上传 | 自己玩 |
| 卡片 / 记忆 | 空（占位目录） | 你的全部 |
| user_config / ai_config | 不含 | 含 |
| 体积 | 小 | 大（带记忆和样本） |

`build_test.bat` 会先跑一次 `build_all.bat` 拿干净包，再复制一份并灌入
`editor_cards/`、`editor_cards_backup/`、`originals/`、`last_saved/`、
`memory/`、`prompt_samples/`、`diff_reports/`、`user_config.json`、`ai_config.json`。

**别把测试包发出去** —— 里面有你自己写的名片和记忆剧情。

改完代码建议先跑这三个检查：

```bash
node tools/web_smoke_test.js     # 前端冒烟（语法错误会让界面空白）
python tools/check_web_refs.py   # 元素 id 引用是否对得上
python -m py_compile editor.py proxy/core_proxy.py
```

## 发版（让用户能自动更新）

编辑器启动 6 秒后会静默查 GitHub 的 latest release，发现新版就在右下角
浮出提示。所以每次发版都要走一遍 Releases：

1. `build_all.bat` 出干净包
2. 把 `dist\WorldApartEditor\` 压成 zip
3. 改 `config.py` 的 `APP_VERSION`（比如 `0.5` → `0.6`）
4. GitHub → Releases → Draft a new release
   - **Tag 必须写成 `v0.6`，和 APP_VERSION 完全一致** —— 检查更新就是拿
     tag 和 APP_VERSION 比数字，对不上会一直提示有新版
   - 附件传那个 zip（检查更新只认 `.zip` 资产）
5. 发布

用户端更新只覆盖程序文件，`editor_cards/`、`memory/`、`ai_config.json` 等
一律不碰（清单在 `config.py` 的 `KEEP_ON_UPDATE_*`）。覆盖前会自动备份到
`backup/update_<时间戳>/`。

## 常见问题

**总结 / AI 补全报 HTTP 401** — 几乎都是打到了第三方 API 却没带对密钥。
在「服务管理 → 记忆总结」填上本地地址并保存（改完失焦即自动保存）。

**角色开始复读** — 查记忆页的事实是否重复累积；查名片示例台词是否太文雅。

**人设不生效** — 到「预览效果」看名片字数是否为 0；确认跑的是新版本。

**导出角色卡后名片没了** — 已知行为，`build_card_file()` 永远写空名片模板，
只能从 `editor_cards_backup/<时间戳>/` 恢复。

更多排查见项目知识库或 `使用说明.txt`。
